# Отчёт о тестировании API-сервиса

## Что это за документ

Этот документ описывает **что именно проверяют автотесты** и **какие результаты ожидаются**.

---

## Группа 1. Авторизация (X-Api-Key)

| ID | Что проверяем | Шаги | Ожидаемый результат |
|----|---------------|------|---------------------|
| AUTH-1 | Успешный вход с правильным ключом | POST /endpoint с `X-Api-Key: qazWSXedc`, `token` (32), `action=LOGIN` | 200 OK |
| AUTH-2 | Неверный ключ | `X-Api-Key: wrong_key` | 401 Unauthorized, `result: ERROR` |
| AUTH-3 | Ключ в другом регистре | `X-Api-Key: QAZWSXEDC` | 401 Unauthorized (ключ регистрозависим) |
| AUTH-4 | Ключ с пробелом в конце | `X-Api-Key: "qazWSXedc "` | 401 Unauthorized  **сейчас 500 — баг** |
| AUTH-5 | Ключ с пробелом в начале | `X-Api-Key: " qazWSXedc"` | 401 Unauthorized  **сейчас 500 — баг** |
| AUTH-6 | Ключ отсутствует | Без `X-Api-Key` | 401, `message: "Missing or invalid API Key"` |
| AUTH-7 | Неверный ключ + неверный токен | `X-Api-Key: qazWSedc`, `token` (невалидный) | 401 (проверка ключа — раньше проверки токена) |

**Известные проблемы:**
- AUTH-4, AUTH-5: приложение возвращает **500** вместо 401, если в ключе есть пробел.

## Группа 2. Валидация токена

| ID | Что проверяем | Шаги | Ожидаемый результат |
|----|---------------|------|---------------------|
| TOKEN-1 | Валидный токен (32, A-Z0-9) | `token` (32), `action=LOGIN` | 200 OK, `result: OK` |
| TOKEN-2 | Токен длиной 33 | `token` = 33 символа | 400, `message: token: должно соответствовать "^[0-9A-F]{32}$"` |
| TOKEN-3 | Токен длиной 31 | `token` = 31 символ | 400, то же сообщение |
| TOKEN-4 | Пустой токен | `token=""` | 400, то же сообщение |
| TOKEN-5 | Пробел в конце | `token="<32> "` | 400, то же сообщение |
| TOKEN-6 | Пробел в начале | `token=" <32>"` | 400, то же сообщение |
| TOKEN-7 | Кириллица в токене | `token="...Ф..."` | 400, то же сообщение |
| TOKEN-8 | Буква G (не hex) | `token="...G..."` | 400, то же сообщение |
| TOKEN-9 | Нижний регистр | `token="a1b2..."` | 400, то же сообщение |
| TOKEN-10 | Спецсимвол | `token="..._"` | 400, то же сообщение |
| TOKEN-11 | Токен отсутствует | Без `token` | 400, `message: "token: не должно равняться null"` |

## Группа 3. Валидация действия (action)

| ID | Что проверяем | Шаги | Ожидаемый результат                                                             |
|----|---------------|------|---------------------------------------------------------------------------------|
| ACT-1 | Валидный LOGIN | `action=LOGIN` | 200 OK                                                                          |
| ACT-2 | Валидный ACTION (после LOGIN) | LOGIN → ACTION | 200 OK                                                                          |
| ACT-3 | Валидный LOGOUT (после LOGIN) | LOGIN → LOGOUT | 200 OK                                                                          |
| ACT-4 | action отсутствует | Без `action` | 400, `message: "action: invalid action 'null'. Allowed: LOGIN, LOGOUT, ACTION"` |
| ACT-5 | `login` (нижний регистр) | `action=login` | 400                                                                             |
| ACT-6 | `NOTHING` (неизвестное) | `action=NOTHING` | 400                                                                             |
| ACT-7 | Пустой action | `action=""` | 400                                                                             |
| ACT-8 | `" LOGIN"` (пробел в начале) | `action=" LOGIN"` | 400 **возвращает 200**                                                          |
| ACT-9 | `"LOGIN "` (пробел в конце) | `action="LOGIN "` | 400        **возвращает 200**                                                                     |

**Известные проблемы:**
- ACT-8, ACT-9: если приложение возвращает **200** на action с пробелом — значит, оно делает `trim()` и прощает ошибку клиента.

## Группа 4. Интеграция с внешним сервисом (WireMock)

| ID | Что проверяем | Шаги | Ожидаемый результат |
|----|---------------|------|---------------------|
| INT-1 | Успешный LOGIN ходит в `/auth` | `/auth`=200, LOGIN | 200, `/auth` вызван **ровно 1 раз** |
| INT-2 | Тело запроса к `/auth` | `/auth`=200, LOGIN | Тело = `token=<token>` |
| INT-3 | Невалидный токен **не** ходит в `/auth` | `/auth`=200, LOGIN с невалидным токеном | 400, `/auth` **не вызван** (`verify(0, ...)`) |
| INT-4 | ACTION без LOGIN **не** ходит в `/doAction` | ACTION без LOGIN | 403, `/doAction` **не вызван** |
| INT-5 | LOGOUT **не** ходит во внешний сервис | LOGIN → LOGOUT | 200, `/auth` и `/doAction` **не вызваны** после LOGIN |
| INT-6 | Ошибка `/auth` (400/401/403/404/500/503) | `/auth`=ошибка, LOGIN | 500, токен **не сохранён** (повторный ACTION = 403) |
| INT-7 | Ошибка `/doAction` (500) | LOGIN → `/doAction`=500 → ACTION | 500, поведение сессии — **по контракту** (жива → 200 / сброшена → 403) |

## Группа 5. Бизнес-логика (состояния сессии)

| ID    | Что проверяем | Шаги | Ожидаемый результат |
|-------|---------------|------|---------------------|
| BIZ-1 | ACTION после LOGIN | LOGIN → ACTION | 200 OK, `result: OK` |
| BIZ-2 | ACTION без LOGIN | ACTION | 403, `result: ERROR` |
| BIZ-3 | LOGOUT без LOGIN | LOGOUT | 403, `message: "Token '<token>' not found"` |
| BIZ-4 | Очистка сессии после LOGOUT | LOGIN → ACTION → LOGOUT → ACTION | Последний ACTION = 403 |
| BIZ-5 | Повторный LOGIN тем же токеном | LOGIN → LOGIN | 409 Conflict, `message: "Token '<token>' already exists"` |
| BIZ-6 | Двойной LOGOUT | LOGIN → LOGOUT → LOGOUT | Второй LOGOUT = 403 |
| BIZ-7 | Многократный ACTION | LOGIN → ACTION ×3 | Все ACTION = 200 |
| BIZ-8 | Цикл LOGIN → LOGOUT → LOGIN | 3 цикла | Каждый шаг = 200 |

## Группа 6. HTTP-уровень

| ID | Что проверяем | Шаги | Ожидаемый результат |
|----|---------------|------|---------------------|
| HTTP-1 | Неверный метод | GET /endpoint | 405 Method Not Allowed ⚠️ **сейчас 500 — баг** |
| HTTP-2 | Неверный Content-Type | POST /endpoint, `Content-Type: application/json` | 415 Unsupported Media Type (или 400) ⚠️ **сейчас 500 — баг** |
| HTTP-3 | Несуществующий путь | POST /unknown | 404 Not Found ⚠️ **сейчас 500 — баг** |
| HTTP-4 | Пустое тело | POST /endpoint, body="" | 400 Bad Request |

**Известные проблемы:**
- HTTP-1, HTTP-2, HTTP-3: приложение возвращает **500 Internal Server Error** вместо 405/415/404.
